# SportHub

Windows-приложение организатора спортивных турниров: команды и игроки, расписание, результаты, турнирная сетка, Excel/графический/JSON-экспорт. Платформа: WPF, .NET Framework 4.8.

## Сборка и проверки

Требуются Visual Studio / Build Tools с WPF и .NET Framework 4.8 targeting pack, NuGet CLI.

```powershell
nuget restore SportHubBase/packages.config -PackagesDirectory packages -NonInteractive
msbuild SportHubBase.Tests/SportHubBase.Tests.csproj /p:Configuration=Release /verbosity:minimal /nologo
& ./SportHubBase.Tests/bin/Release/SportHubBase.Tests.exe
```

Исполняемые проверки не требуют дополнительных тестовых пакетов. Ненулевой код завершения означает ошибку. Для проверки SQL Server:

```powershell
$env:SPORTHUB_TEST_SQL_SERVER = '(localdb)\MSSQLLocalDB'
& ./SportHubBase.Tests/bin/Release/SportHubBase.Tests.exe
```

SQL-проверка создаёт и удаляет отдельную БД с уникальным именем `SportHubTests_<GUID>`, не использует рабочую SportHub. Без переменной SQL-проверка явно пропускается. CI запускает сборку и остальные проверки на push/PR, а также перед публикацией релиза по тегу.

## Проверка обновлений

При запуске приложение асинхронно проверяет последний опубликованный релиз GitHub. Ручная проверка доступна через меню «Настройки» → «Проверить обновления». Репозиторий задаётся ключом `GitHubRepository` в `SportHubBase/App.config`, по умолчанию `SniperTormenta/SportHub`. Токен для публичного репозитория не требуется.

Если доступна более новая версия, показывается окно с описанием изменений:

- **«Да»** — открыть скачивание `SportHubBase-<версия>.zip` в системном браузере. Если подходящий архив отсутствует, открывается страница релиза с файлами. Приложение продолжает работать; установка выполняется пользователем.
- **«Пропустить»** или закрытие окна — не предлагать обновление до следующего запуска SportHub. Пропуск не сохраняется на диск, старые настройки AutoUpdater.NET игнорируются.

Релиз публикуется с числовым тегом, например `v1.2.3`. Workflow устанавливает версию сборки из тега перед упаковкой. Черновики и предварительные релизы не предлагаются. XML-манифест старого механизма продолжает входить в релиз для совместимости, новая проверка его не читает. При отсутствии сети фоновая проверка не прерывает работу, ручная сообщает об ошибке.

Протокол проверки: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release).

## SQL Server

Встроенные общие логин и пароль удалены. Для удалённого подключения задайте `SPORTHUB_SQL_CONNECTION_STRING` в окружении пользователя и перезапустите приложение. Значение должно быть полноценной строкой подключения к настроенной БД; адрес, выбранный в приложении, заменяет Data Source, остальные параметры берутся из переменной. Можно использовать Windows-аутентификацию. Для локального адреса без внешней конфигурации применяется Windows-аутентификация к базе SportHub.

Не помещайте реальное значение переменной в Git, скрипты сборки и клиентские исходники. Старый встроенный пароль необходимо сменить на сервере: удаление из текущей версии не удаляет его из истории и старых дистрибутивов. Для удалённых серверов используйте корректный сертификат; проверка сертификата автоматически отключается только для распознанных локальных адресов.

Первое подключение проверяет и обновляет схему. Если у рабочего пользователя нет DDL-прав, миграцию должен выполнить администратор. Все работающие клиенты должны быть обновлены: старые версии не проверяют Revision и могут обходить защиту конфликтов. Для старого турнира без реквизитов организатора учётные данные назначает администратор; захват турнира первым вошедшим пользователем отключён.

## Данные и резервные копии

База находится в `%LOCALAPPDATA%/SportHub/sporthub.db`, автоматические копии — в соседней папке `Backups`, журнал — в `Logs`. При первом запуске новой версии база из каталога приложения переносится копированием, исходник остаётся на месте.

Копия создаётся перед миграцией, восстановлением, импортом команд и удалением турнира; при обычных сохранениях — с интервалом не менее пяти минут. Хранятся последние 20 автоматических копий. Это копии SQLite, включая локальные аккаунты и кэш удалённых турниров; резервное копирование самого SQL Server настраивается отдельно.

В главном окне откройте **«Настройки» → «Резервные копии локальной базы»**:

- **«Сохранить резервную копию»** — выбрать место для отдельного файла БД.
- **«Восстановить из копии»** — проверить файл, подготовить восстановление и закрыть приложение. При следующем запуске текущая база сначала сохраняется, затем заменяется выбранной копией. Данные на сервере не меняются; при подключении сервер снова обновит удалённый кэш.

Копии содержат персональные данные и хеши паролей. Храните их с теми же правами доступа, что и рабочую БД.

При конфликте сохранение отклоняется до изменения команд и матчей. Закройте и откройте турнир либо выполните синхронизацию удалённого турнира, затем повторите ввод. Автоматического слияния результатов пока нет. При неудачном удалении на сервере локальная копия сохраняется; для удаления только кэша используйте отключение турнира.

## Текущее состояние

Реализованы круговой формат, плей-офф и швейцарка. Швейцарская жеребьёвка использует поиск без повторных встреч с ограничением сложности; при невозможности подобрать пары выдаёт ошибку. Это не сертифицированная реализация регламента конкретной федерации. «Группы + плей-офф» пока в разработке.

Операции турнира и подготовка расписания выделены из ViewModel в сервисы. Сетевые операции остаются синхронными, дальнейшее разделение UI и переход на async выполняются постепенно. JSON-хранилище сохранено как старый резервный вариант и не используется штатной конфигурацией; контроль версий реализован для SQLite и SQL Server.

Публикация сайта, QR-коды, API, серверные роли, история изменений и синхронизация отложены до стабилизации текущей версии. Текущие клиентские флаги организатора не заменяют серверную авторизацию. Roadmap: [AGENTS.md](AGENTS.md).
