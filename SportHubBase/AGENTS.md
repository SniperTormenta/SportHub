# SportHubBase

## Назначение и ограничения

WPF-приложение организатора спортивных турниров на .NET Framework 4.8. Не переписывать платформу в рамках исправлений и не добавлять новые зависимости без необходимости. Комментарии и документация — на русском языке. Общие соглашения и Roadmap находятся в [корневом AGENTS.md](../AGENTS.md).

## Основные части

- В карточке команды «Убрать из турнира» удаляет команду и все её матчи, включая сыгранные. `TournamentOperationsService.RemoveTeam` сохраняет агрегат с проверкой версии и откатом модели при ошибке; таблица рассчитывается по оставшимся матчам. Их номера, туры, даты и результаты не изменяются. Для сетки удаляются встречи команды без автоматического продвижения и перестройки оставшихся связей.
- `TournamentWindow.xaml`, `ViewModels/ScheduleViewModel.cs` — поиск встреч по части названия команды или номера матча. Флажок «Точное совпадение» включает сравнение полного названия или номера без учёта регистра и пробелов по краям; переключение обновляет общий список и списки туров.
- `View/ConnectRemoteTournamentWindow.*` — добавление серверного турнира: адрес, список и состояние поиска. Пока поддерживается только SQL Server с совместимой схемой SportHub. Изменение адреса сбрасывает результаты; добавление использует адрес последнего успешного поиска.
- `MainWindow.xaml` — компактный список турниров: создание и добавление с сервера рядом с заголовком, поиск и фильтры над списком, счётчик и пустое состояние. Резервные копии локальной базы и проверка обновлений находятся в меню «Настройки».
- `App.xaml.cs` — Simple Injector, проверка графа зависимостей, обработка ошибок запуска и интерфейса, один процесс приложения на пользователя.
- `Models/` — турнир, команды, игроки, матчи, сетка. `ScorePair.cs` содержит общий разбор неотрицательного числового счёта.
- `Services/DynamicStorageService.cs` — маршрутизация локальных/удалённых операций и кэширование. Изменение состава и матчей через этот сервис сохраняет агрегат с проверкой версии.
- `Services/TournamentRevisionService.cs`, `StorageConflictException.cs` — контроль версии перед изменением агрегата. SQL Server использует UPDLOCK/HOLDLOCK; SQLite — транзакцию записи. Версия объекта меняется только после commit.
- `Services/TournamentIntegrityService.cs` — восстановление старых связей по уникальным названиям и обновление отображаемых названий по идентификаторам, в том числе в сетке.
- `Services/TournamentOperationsService.cs` — сохранение, завершение, удаление и импорт с восстановлением модели при неудаче.
- `Services/TournamentScheduleService.cs` — подготовка расписания и генерация тура; загрузка швейцарки не удаляет историю, смена сторон сохраняет правильную ориентацию счёта.
- `Services/DatabaseBackupService.cs` — SQLite Online Backup, проверка целостности, ротация 20 автоматических копий, подготовка восстановления на следующий запуск.
- `Services/ErrorLog.cs` — локальный журнал, ротация 30 дней, понятные сообщения об ошибках. Не записывает текст исключений драйверов и значения параметров/строк подключения.
- `Services/UpdateService.cs`, `Models/UpdateRelease.cs`, `View/UpdateAvailableWindow.*` — асинхронная проверка последнего опубликованного релиза через GitHub API, сравнение числовых версий, окно «Да / Пропустить». «Да» открывает GitHub в системном браузере; пропуск и закрытие окна действуют только до следующего запуска. Сохранённые настройки старого AutoUpdater.NET не используются, автоматическая установка не вызывается. Репозиторий задаётся ключом `GitHubRepository` в `App.config`.
- `Services/Scheduling/` — Бергер, плей-офф и швейцарка. Швейцарка использует ограниченный поиск с возвратом, не создаёт повторные встречи при тупике. Многоэтапный формат пока является заглушкой.
- `Services/Result/`, `Services/Statistics/` — таблицы, очки, статистика. Проверять победы, ничьи, технические поражения и BYE.
- `Services/Export/TournamentJsonExportService.cs`, `Models/Export/ExportModels.cs`, `Interfaces/ITournamentJsonExportService.cs` — отдельный JSON-контракт для последующей публикации. Не экспортировать реквизиты организатора/SQL.
- `ViewModels/`, `View/` — привязки и окна. Пакетное применение результата использует `Match.BeginUpdate()`: подписчики получают одно уведомление с пустым именем свойства и должны его обрабатывать.

## Схема и совместимость

- `Tournament.PreserveSchedule` (`preserveSchedule` в JSON, `Tournaments.PreserveSchedule`: SQLite INTEGER / SQL Server BIT, по умолчанию 0) запрещает автоматическую генерацию расписания после снятия команды, даже если встреч не осталось. Явная генерация нового тура швейцарки доступна; импорт нового состава сбрасывает флаг. В JSON сетки `preserveStructure` запрещает восстановление связей по позициям и повторное продвижение результатов при загрузке; `BracketMatch.matchNumber` сохраняет номера оставшихся встреч.
- `Tournaments.Revision`: SQLite INTEGER / SQL Server BIGINT, исходная версия старых записей — 0. Обычная запись увеличивает её; обновление удалённого кэша сохраняет серверную версию без локального инкремента.
- `Matches.Team1Id`, `Team2Id`: SQLite TEXT / SQL Server NVARCHAR(64), nullable для старых данных, BYE и ещё не определённых участников сетки.
- Строковые названия и поля счёта оставлены для совместимости. Приоритет ссылки на команду — ID. Старые записи получают ID по уникальному названию при загрузке/сохранении.
- `ResultRow.Draws` учитывается в расчёте, кэше результатов и JSON-экспорте.
- SQLite хранится в `%LOCALAPPDATA%/SportHub/sporthub.db`. При первом переходе существующая база из каталога приложения копируется через SQLite Backup API; исходная база не удаляется.
- Перед миграцией и восстановлением создаётся копия. При обычных сохранениях — не чаще одной копии в 5 минут; перед импортом/удалением — принудительная копия.
- Восстановление касается только локальной БД, включая кэш. Серверные данные не откатываются.
- Не использовать `CacheTournament` для обычной записи: этот метод намеренно заменяет кэш без проверки локальной версии.
- Сетевые права пока проверяются на клиенте. API и серверная авторизация — следующий этап, не считать текущую схему достаточной защитой публичного сервиса.

## Проверка изменений

Собирать и запускать проект [SportHubBase.Tests](../SportHubBase.Tests/SportHubBase.Tests.csproj) по инструкции из корневого файла. В нём проверяются расписания, счёт, таблицы, сохранение, миграция, восстановление и конфликты. SQL-интеграция включается отдельной переменной окружения. Не проверять миграции на пользовательской БД.
