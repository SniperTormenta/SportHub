## Структура

- `SportHubBase/` — приложение WPF, .NET Framework 4.8, старый формат проекта MSBuild, зависимости через `packages.config`.
- `SportHubBase.Tests/` — исполняемые регрессионные проверки без новых NuGet-зависимостей. Возвращают ненулевой код при ошибке.
- `SportHubBase.slnx` — решение приложения и проверок.
- `.github/workflows/ci.yml` — сборка Release и проверки на push/PR.
- `.github/workflows/release.yml` — сборка, проверки и публикация по тегам `v*`.
- `README.md` — настройка, сборка, резервное копирование и ограничения.

## Архитектура и данные

- Снятие команды через её карточку удаляет все её встречи и пересчитывает таблицу по оставшимся. Расписание остальных команд сохраняется без изменения пар, туров, номеров, дат и счёта. `Tournaments.PreserveSchedule` (SQLite INTEGER / SQL Server BIT, исходное значение 0) сохраняет запрет автоматической перестройки после удаления; в JSON сетки сохраняются `preserveStructure` и номера матчей `matchNumber`. Регрессионные проверки покрывают повторную загрузку, пустое расписание, сетку и конфликт сохранения.
- Поиск встреч в окне турнира поддерживает флажок «Точное совпадение»: полное название команды или номер матча без учёта регистра и пробелов по краям. По умолчанию используется поиск по подстроке.
- Окно добавления с сервера поддерживает только SQL Server со схемой SportHub; список найденных турниров привязан к адресу поиска и сбрасывается при его изменении.
- Главное окно: создание и добавление турнира с сервера, поиск и фильтры; обслуживание локальной базы и проверка обновлений вынесены в меню «Настройки».
- Подробные инструкции приложения: [SportHubBase/AGENTS.md](SportHubBase/AGENTS.md).
- Основной путь хранения: `DynamicStorageService` → SQLite / SQL Server; JSON-хранилище оставлено для совместимости и не зарегистрировано в приложении.
- SQL-реквизиты поступают из `SPORTHUB_SQL_CONNECTION_STRING` или вводимой строки подключения. Не возвращать встроенные общие логин/пароль.
- `Tournament.Revision` — оптимистическая блокировка. Проверка и запись версии выполняются в одной транзакции до обновления дочерних данных.
- `Match.Team1Id` / `Team2Id` — устойчивые ссылки на команды; строки названий сохраняются для интерфейса и совместимости.
- `ScorePair` — общий числовой разбор счёта; старые строковые поля сохранены.
- Новые столбцы добавляются при запуске; ошибки миграций не скрываются.
- Обновления: `UpdateService` асинхронно читает GitHub Releases API; `Models/UpdateRelease.cs` разбирает версию и выбирает архив. Окно «Да / Пропустить» открывает скачивание в браузере или откладывает предложение до следующего запуска без записи пропуска на диск. Настройка — `GitHubRepository` в `App.config`.
- Workflow релиза устанавливает AssemblyVersion/AssemblyFileVersion из числового тега `v*`, чтобы скачанная версия не предлагалась повторно.

## Проверки

```powershell
nuget restore SportHubBase/packages.config -PackagesDirectory packages -NonInteractive
msbuild SportHubBase.Tests/SportHubBase.Tests.csproj /p:Configuration=Release /verbosity:minimal /nologo
& ./SportHubBase.Tests/bin/Release/SportHubBase.Tests.exe
```

Для SQL-интеграции установить `SPORTHUB_TEST_SQL_SERVER`, например `(localdb)\MSSQLLocalDB`. Проверки создают отдельную БД `SportHubTests_<GUID>` и удаляют только её. Нужны права CREATE/DROP DATABASE. При отсутствии переменной SQL-проверка явно пропускается; SQLite и доменные проверки выполняются всегда. Тесты используют изолированные временные каталоги.
